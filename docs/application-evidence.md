## Evidence that cannot be manufactured by a code change

- **Published validation:** Push/PR CI runs, release/package parity and deployed
  smoke checks require separately authorized publication. A local pass and a
  workflow definition are not a hosted green run.
- **Real demonstrations:** Record an installed extension with version, source
  revision if known, browser and date; distinguish actual retrieval from sample
  data. Record bot scenarios in a private test server with synthetic members,
  never a production roster. A diagram is explanation, not an operational video.
- **ML generalization:** Independent labels or content-disjoint assessment data
  must be collected under a frozen protocol. Preserve historical scores and
  explain overlap; never rebrand selection or refit results as final assessment.
- **Accessibility:** Keyboard tests do not establish a screen-reader assessment.
  Stored subject descriptions and physical Safari/iOS testing need real evidence;
  generic node IDs/orientation alone do not describe a photograph's subject.
- **Systems-language proof:** Link only existing coursework/projects the owner
  can explain, after checking publication permission. C/C++ and Java skill labels
  are not proof of a shipped graphics pipeline.
- **Client process and contribution:** Add actual feedback or collaboration
  examples only from the owner's account or records. Do not manufacture adoption,
  time savings, testimonials, user counts or AI-assisted-review anecdotes.
